# 요구 사항과 NCS 연결

기본 제한 시간은 30초, 코인은 10개입니다. 같은 ID는 한 라운드에 한 번만 수집합니다.
메뉴·플레이·결과를 구분하고, 결과에서 다시 시작하거나 메뉴로 돌아갑니다.
최고 점수를 저장합니다. 설정은 현재 라운드를 바꾸지 않고 다음 시작에 반영합니다.
스테이지 로드와 설정 준비 중에는 시작을 잠급니다. 로드 실패 후 재시도할 수 있어야 합니다.

| 목표 | 프로젝트에서 확인할 내용 |
|---|---|
| G1 요구 사항 분석 | 대상 플랫폼, 입력, 저장, 성능, 실패 시 동작 |
| G2 라이브러리 선정 | Input System·uGUI·Addressables 선택 이유 |
| G3 개발 환경 구성 | Editor·모듈·패키지·빌드 프로필 |
| G4 자료 구조 설계 | CoinRound의 상태와 HashSet 수집 ID |
| G5 게임 로직 | 수집·제한 시간·결과·재시작 |
| G6 플랫폼에 맞는 알고리즘 | UI 갱신 조건과 성능 비교 |
| G7 플랫폼별 코딩 | 입력·저장·종료·콘텐츠·네트워크 |
| G8 테스트·오류 수정 | 플랫폼 실행·로그·실패 재현·복구 |
| G9 프로파일 기반 최적화 | 같은 조건에서 개선 전후 측정 |

실행 가능한 소스가 있다는 이유만으로 G1~G9를 모두 달성한 것으로 채점하지 않습니다.
설계 설명, 테스트 기록, 플랫폼별 실행 및 측정 자료를 함께 제출합니다.
공식 평가 기준과 교사용 답안은 교육과정 저장소의 비공개 문서에서 관리합니다.
